# CPU recognition/alignment for captions and cleanup

Tiny is a setup baseline, not evidence of usable recognition. A real recording omitted a complete repeated instruction with tiny; base.en recovered it. The result is one regression, not proof across speakers. For authorized recognition improvements, `node scripts/setup-model.mjs base.en --download` obtains/verifies the official ~142 MiB model separately; `studio transcribe <id> --model base.en --language en --dtw true` leaves the tiny config and prior outputs intact. DTW points are diagnostics, not word intervals.

For actual acoustic alignment, install the separate CPU runtime with `npm.cmd ci --prefix tools/alignment --ignore-scripts --no-audit --no-fund`, then `node scripts/setup-alignment.mjs --download` obtains/verifies the ~95 MB English quantized CTC model. These are optional downloads for the needed feature, not GPU/Python/global installations. No media is uploaded. Downloads/runtime/model remain recipient-local; manifests and original code are tracked. Missing tools/hash mismatches fail clearly.

`node scripts/align-transcript.mjs <public-relative original transcript> <associated prepared WAV>` uses that transcript run's full-section 16 kHz audio, with chunked CPU inference and original Viterbi CTC logic. It preserves text, aligns character evidence and derives word intervals from model cells. It saves a separate JSON, diagnostics, source/WAV/model hashes, low-confidence warnings and strict structural validation; no timestamp clamping or stretching. Unsupported languages/text, incomplete paths, oversized blocks and invalid aligned output fail. Existing recognized phrases can remain intervals; no individual times are fabricated inside them. Only import a valid aligned file with studio transcript before applying cleanup. Review a full retained readback and acoustic evidence at joins before rendering.

The primary command is `studio prepare-speech <id> --language en --setup true` (setup only when missing). It connects the tools, checkpoints recognition before alignment, validates bound audio, imports word intervals and resumes without rerunning completed work. Individual helpers remain diagnostic tools, not a fallback around its guards. Words inside native phrases are aligned separately from audio; original search windows never become invented per-word intervals.

Limits: English, one original source section, no diarization, no automatic reliability guarantee. Standalone numbers0–99 use explicit English pronunciation labels while preserving caption spelling; ambiguous numeric/multilingual text stops for review. Recognition corrections require evidence and remain proposals until confirmed. CTC can force a poor match to incorrect words; low confidence must remain visible. Structural checks, model scores and independent greedy acoustic text do not constitute listening review. Do not align an unspoken script as though it was the transcript. Do not call low-confidence boundaries verified.

Official sources: [whisper.cpp models](https://github.com/ggml-org/whisper.cpp/blob/v1.9.2/models/README.md), [ONNX Node CPU runtime](https://onnxruntime.ai/docs/get-started/with-javascript/node.html), [English acoustic model](https://huggingface.co/facebook/wav2vec2-base-960h), [CTC alignment background](https://docs.pytorch.org/audio/stable/tutorials/ctc_forced_alignment_api_tutorial.html). No upstream tutorial code was copied; the project's path implementation is original.
