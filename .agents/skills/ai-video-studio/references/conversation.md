# Short guided conversation

Use studio next-question to resume the appropriate stage; it returns agent-facing questions/actions, not automatic user approval or a separate UI. Read permission-workflow.md. Do not repeat answered questions. Avoid the phrase “display name, audience and tone.” Name/logo/watermark are optional; retain neutral internal defaults when absent. Ask about an audience or tone only for a concrete editing decision, in plain language, normally in the per-video brief rather than the opening.

1. After setup, ask only: “Do you have a website or brand materials you’d like me to use? Share a link or attach files here, or say ‘use simple defaults.’” Do not bundle the reference request into this question. Save studio onboarding-answer --step materials --value supplied|skip based on the actual answer; neither time passing nor an empty response means skip.
2. Separately invite: “Attach 1–3 videos whose editing style you like. Tell me what you like—or I can help identify it. You can also say ‘skip references.’” Save onboarding-answer --step references --value supplied|skip. Verify original attachment access, import files automatically and follow intake.md; if files are inaccessible explain the limitation and accept a full local path. Do not ask for filenames as a prerequisite to attaching files. Supplied means wait for accessible files, not invent an analysis. Analyze captions/framing/graphics/pacing/transitions/sound with observation limits; never copy creator content/branding. Do not assume another chat's attachments are available.
3. Create the proposed reusable direction and motion preview using onboarding.md. Pause for actual review/approval, not after merely rendering a sample. After approve-brand succeeds, continue the same response with the next action: “Your style is ready. Attach the video you’d like me to edit here.” If footage is already supplied, import it and proceed to the brief instead. Do not end with only “ready”, “done”, or an open-ended “anything else?” that makes the user ask what comes next. Preserve older approvals and completed steps.
4. Import raw footage as footage, not references. Inspect it before choosing edit defaults. Then, BEFORE FIRST DRAFT, show one short free-text question box when the host offers request_user_input_async or an equivalent input tool: “What would you like from this edit? You can give an opening on-screen hook, target length, and any editing instructions—or say ‘use sensible defaults.’” Offer Use sensible defaults as a suggested answer. This is a conversational box, not an upload application. Request file attachments in the normal chat, not a text-only question tool. If no question tool exists, ask the same concise question in chat. Do not make three long mandatory forms; one natural-language answer suffices. When these instructions are already supplied, summarize/save them and skip the redundant question.
5. The agent writes a local JSON brief answer, then runs studio brief <id> --file <answer.json>. Shape: {instructions: string, hook?: string|null, targetSeconds?: number|null, platform?: string, cleanup?: boolean}. Save the user's actual request or their explicit acceptance of defaults; do not mark answered before a reply. An omitted hook means no invented hook; omitted duration means use the inspected short clip or a sensible source-bounded section. Essential ambiguity merits one focused question; optional gaps do not block the draft. For requested take cleanup, save cleanup=true and follow take-cleanup.md before timed effects. Apply exact requested hook with studio set --title, select duration using intake before transcription, and implement graphics/effects through existing commands. The brief command stores intent; it does not itself implement every edit. No need for the user to supply frames, paths to internal folders or JSON.
6. Offer an optional script in the edit-brief question: attach or paste it; natural paraphrases are allowed. Do not add a mandatory questionnaire or ask again when supplied/declined. Use script-import/script-analyze and [script-assisted review](script-assisted-review.md); script text never becomes invented captions or timestamps.
7. For requested captions or cleanup, run prepare-speech before cut selection/rendering. It performs the required recognition and acoustic alignment, reusing completed results. Do not switch to phrase estimates or raw CLI when a quality guard fails. Review script coverage, full retained sentences and uncertain wording; the user does not debug software or supply frames. New video records require the brief before draft rendering. Existing projects remain resumable; use supplied answers rather than asking again. Show the playable draft and accept plain-language changes, then keep the current-revision approval/export gates.

This is agent orchestration with persistent state and a first-draft guard. Question-box presentation depends on the host tool; structural tests cannot establish actual UI behavior or reference/audio perception.
