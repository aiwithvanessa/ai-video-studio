# Intake, local transcription and review

Use [short guided conversation](conversation.md). Invite raw footage attachments directly; no filename prerequisite. Before the first draft, collect the optional hook, length and free-text instructions (or accepted defaults), save studio brief and apply it before choosing section/transcription.

Follow [automatic media import](intake.md). Choose the video ID internally and import readable original media with studio import-media --role footage --video <id> --source <absolute readable path>. Use the returned asset with studio intake <id> --source <asset> --duration 15 --title "Title". Intake probes metadata, snaps the section to frames, fits even dimensions without upscaling, preserves source/audio and updates the brief. Do not make users manage the folder structure.

For English captions or speech cleanup use `node scripts/studio.mjs prepare-speech <id> --language en --setup true`. Disclose one coherent local CPU plan: whisper.cpp engine, ~142 MiB base.en model, separate CPU runtime and ~95 MB acoustic model, all project-local. No Python/GPU/cloud upload. Omit setup true when installed. This command performs recognition, acoustic word alignment, strict validation and caption import; current valid speech data is reused instead of overwritten or rerun. Optional `--vocabulary` can contain short known proper names, not a full script. No extra conversational consent per step when the edit/setup already authorizes it. Platform network restrictions can require actual system approval. Other languages are an explicit current limitation; no silent inaccurate fallback.

studio transcribe <id> --language auto prepares the exact composition section. The extraction explicitly maps audio-stream offset relative to the media origin, resamples to 16kHz and retains section silence; it does not move words to a volume threshold. Raw engine JSON, diagnostics and WAV stay in dated .local runs. Automatic transcript JSON/text is dated under the video's generated/transcripts folder. Engine millisecond offsets become section-relative seconds; t_dtw is not used as an interval. The timing kind is labelled engine-estimated word-split segments, not certified word alignment.

src/lib/timing.mjs rejects nonfinite, negative, reversed/zero, unordered/overlapping and out-of-section intervals. Invalid output is preserved and not imported. No clamping, invented boundaries, global shift or dropping actual speech. Phrase-level engine segments are warnings. Listening review is still required even if structure passes.

Import acoustic output with studio transcript <id> --file <public-relative transcript> (prepare-speech does this). Numeric/raw phrase validity alone cannot pass the render or cleanup guards. To correct recognition/timing, the agent prepares a patch with baseSha256, expected text and an honest review note, writes a separate copy, and re-aligns changed recognized wording when needed. No invented timing for inserted words. The beginner supplies ordinary-language corrections, not JSON. Missing audio/unsupported language/tools must be explained; use an explicitly uncaptioned, uncut preview rather than fabricate text or destructive cuts.

For a corrected recognition proposal run `prepare-speech <id> --language en --recognition-file <public-relative proposal>`. It verifies the original source/section and prepared WAV hash, reuses audio and computes new word intervals instead of retaining old timing for added words. Existing valid edited timelines are already prepared: do not restore/retranscribe them for a mere styling revision. Review recognized wording against the script, treating paraphrases as valid and checking uncertain names/clauses. A larger model can omit repeats too; the optional ~190 MB small.en-q5_1 model is a diagnostic second pass, not the editing default or proof of correctness.

Official FFprobe/FFmpeg/Remotion sources remain recorded in provenance.md. One successful fixture does not establish accuracy for future clips.

If OffthreadVideo frame extraction fails, inspect source-frame spacing and available memory before guessing. The optional studio prepare-render-source <id> helper creates a same-size short-GOP H.264 working copy under that video’s generated folder, retains source/transcript bindings, compares section metadata and decoded audio hashes, and clears video approval. It does not overwrite the original or rerun transcription. Render-source bytes are included in export fingerprints. This is a compatibility recovery, not automatic proof of a codec defect; rerender and inspect frames. Keep concurrency 1/cache128MiB; do not increase cache beyond actually available RAM.

The maintained footage composition now uses Video from @remotion/media (exactly4.0.542), following official guidance at https://www.remotion.dev/docs/media/video. The tested Windows OffthreadVideo path failed on both an intact HEVC source and a verified H.264 copy under low available RAM. A render copy alone is not an established fix. The media component fails clearly instead of silently falling back to that decoder. Original source/transcript hashes remain authoritative.
