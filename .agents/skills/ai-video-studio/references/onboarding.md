# Identity and editing-style onboarding

Follow [low-friction project work](permission-workflow.md); verify the active writable folder once and do not repeat technical permission questions for already authorized setup. Follow [short guided conversation](conversation.md), keeping brand materials and reference uploads as separate questions. Name/audience/tone are not required opening questions; use internal defaults and ask only when a concrete decision needs it. Resume studio status; preserve existing identity answers and approvals. Setup details are in START-HERE. Before brand approval, explicitly offer BOTH a website/brand materials and optional 1–3 videos whose editing style the user likes. Do not treat lack of response as declining references. Ask what they like; offer to identify the style if unsure. Without references, offer a polished default: readable short white captions, optional highlight, restrained title/callout entrances, steady face framing, breathing room between points, minimal transitions, original voice, optional sparse approved sounds and no automatic music.

Follow [automatic media import](intake.md). Explicitly offer website/brand materials and optional reference videos, using verified readable attachment originals where available or a supplied local path that the agent imports. Do not instruct users to organize or copy project folders as normal intake. Preserve originals; imported materials remain private and excluded from releases.

Follow [close reference matching](reference-matching.md). A supplied reference requires an explicit bound referenceMatch and measured captionAppearance, not the generic large-number demo. Preserve outline versus backing, typography, placement and layout; state brand overrides/approximations. Probe actual reference metadata; inspect representative frames AND motion/playback/audio where tools permit. For captions, framing, graphics, pacing, transitions and sound record observed details with time ranges/method, or unassessed and a specific limitation. Still frames do not establish pacing, transitions or sound. Ask only meaningful missing questions; never fabricate observations. Do not copy creator content/logos/branding or extract their sounds.

Save a private analysis JSON in .local: referencesChoice supplied|declined; references [{asset:shared/references/file.mp4,userLikes:string,analysis:{captions,framing,graphics,pacing,transitions,sound}}], each analysis entry {status:observed|unassessed,notes:string}; direction with the same six string fields describing PROPOSALS; captionMode plain|highlight. Synthesize recipient identity plus references; proposed choices are not observations. Use studio style-plan --file <analysis.json>. It preserves the prior identity approval separately and invalidates video approvals. BRAND.md stores configured reusable direction; local state retains source evidence/hash and limitations. Per-video briefs contain deviations, not competing universal rules.

Show the eight-second BrandPreview at its verified local URL and summarize all six proposed choices. This uses real frame-driven caption groups and a callout entrance, without private footage or copied reference content. It is silent and illustrative: it does not demonstrate camera framing, a real footage zoom, or a finished sound mix. If a proposed significant effect needs demonstration before acceptance, adapt this original preview using existing components; do not pretend prose implements it. Plain-language changes update the proposal and preview. Only record approve-brand after explicit approval of the current identity AND style proposal. Missing/new style review must resume without erasing prior identity approval or repeating supplied answers. Final video approval remains separate. After style approval, immediately invite the first footage attachment; if footage is already present, proceed to the short editing-brief question. Never end only with a completion announcement.

Optional style-plan captionAppearance: {textColor: six-digit hex, highlightColor: six-digit hex, backing: none|dark, highlightWords?: string[]}. The saved brand style drives shared captions and the preview; intake uses captionMode for new videos. Select important words from actual content when requested; omit highlightWords to highlight every active word. No phrase/timestamp modification is needed for styling. Real footage remains the reel background. Neutral preview placeholders are labelled; do not treat a solid brand canvas as the required reel background. Readability, especially coloured words on varied footage, needs frame/playback review.

Caption placement must be matched per layout/shot, using multiple reference frames. Do not apply one stacked-layout position to every scene. captionAppearance.centerYRatio anchors the caption block centre in frame-height units and overrides bottomRatio; inspect visible glyph bounds since font metrics can still differ by pixels. referenceMatch.previewScenes may contain ordered nonoverlapping {start,end,layout,captionCenterYRatio} entries for the eight-second sample. These are agent-managed demo settings, not offsets to speech timestamps. Captions accepts captionCenterYRatio per scene for reuse; actual editing layouts must deliberately supply it when their scene changes.
